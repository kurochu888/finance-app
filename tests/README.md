# 測試

改完 `app.template.html` 之後:

```sh
python3 build.py     # 產生三個版本
tests/run.sh         # 跑全部測試
```

| 檔案 | 測什麼 |
|---|---|
| `smoke.js` | 功能與計算:四個小分頁能不能畫、損益、XIRR、曝險、還款分段利息、配息、備份還原、CSV、圖表互動。三個版本各跑一次 |
| `hunt.js` | 邊界情況:空白或重複的標的代號、刪掉還有紀錄的標的、賣超過持股、未來日期的還款、負數輸入、配息紀錄改金額、預設標的刪掉後記買賣、兩列同代號(壓力測試/CSV 不重複算、重複列刪得掉)、未來日期的動用(到那天才算借款與利息);證交所回應最後一列是「--」、抓報價途中 state 被雲端同步換掉 |
| `charts.js` | 圖表:兩點、一年 250 點、滿載 1000 點、全等值、負數、極大極小、有缺洞;檢查座標不跑出畫布、沒有 NaN、可點區域數量,以及點下去說明列與游標線會不會跟著動 |
| `trend.js` | 均線趨勢訊號(`computeTrend`)、分割還原(`mergeHistory`)、`normalize()` 防呆、曝險目標的代數解(`computeExposurePlan`)|
| `backtest.js` | 均線策略回測(`runBacktest`):跟 `computeTrend` 同一段價格路徑,狀態機判斷是否逐行一致;淨值曲線不出現負值、MDD 不是正數;全押買進真的扣了手續費;`monthEndSample` 取樣正確 |
| `audit.js` | 版面密度盤點:每個小分頁有幾張卡、幾個大字、幾段說明、多少字。不是通過/失敗,是給人看的數字,用來檢查有沒有又變雜亂。**故意不放進 `run.sh`**,要看的話手動 `node tests/audit.js` |
| `cloud.js` | 雲端同步(假後端):首次拉取、寫入回音(包括較早一次寫入的回音晚到)、別台改動、打字中先擱著、擱著的改動套用時跟本機還沒推上去的修改逐筆合併、寫入失敗、壞資料防護、匯入驗證 |
| `help.js` | 說明頁與程式是否一致:手續費率、證交稅、快照與備份份數、報價過期天數、空間提醒門檻,以及說明裡提到的功能位置(例如「還款在紀錄分頁」)是否真的如此 |
| `ids.js` | 重構後的完整性:同一畫面沒有重複 id、`<div>` 開合相符、輸出不含樣板殘骸(`${`、`undefined`、`NaN`),以及 refreshLeverage 要更新的每個 id 都真的存在 |
| `stress-live.js` | 壓力測試在打字時要即時更新(不能等到失焦才算) |
| `update.js` | 「有新版」提示:線上換版會跳提示、版本相同不跳、點下去先存檔再重新整理、單檔版/Artifact 版不檢查 |
| `items.js` | 每月快照的資產/負債細項:跨月固定、「比上月」、改名接得起來、手動改過的月份不被覆蓋;舊版分頁把細項/分割記錄丟掉寫回雲端時要保留本機的 |
| `fuzz.js` | 隨機操作壓力測試:隨機點畫面上的按鈕、欄位填各種怪值(負數、1e309、亂碼日期、HTML)、偶爾跨日跨月,每一步檢查不丟例外、畫面沒有 NaN/undefined、state 數字都有限、淨資產=資產−負債、normalize 冪等。`run.sh` 跑 3 組 × 800 步;要更狠手動跑 `node tests/fuzz.js 3000 <種子>`,換版本用 `FUZZ_FILE=finance_app_artifact.html` |
| `semantic.js` | 計算正確性(隨機 400 組買賣/配息/動用/還款):總損益 = 市值+賣出+配息−投入−利息、逐筆回放的持股 = heldShares、XIRR 代回去真的是根;同一天先記賣出後記買進不能被當成賣超 |
| `oracle.js` | 照 app 的建議實際做一次再讓 app 重算:照方案A/方案B 的金額兩檔各半買進,曝險要剛好等於目標;股價照槓桿倍數真的調降,重算的市值/淨值/曝險要跟壓力測試預測一樣(隨機各 300 組) |
| `storage.js` | 瀏覽器空間(5MB)快滿:主資料一定存得進去,先清可重抓的回測快取、再刪最舊的備份;主資料大到放不下一份備份時要提醒 |
| `longrun.js` | 15 年長期使用:把時鐘換掉,模擬每天開 app、記帳、買賣、大盤下跌時模擬動用房貸、曝險過高時模擬減碼還款,追蹤資料量、localStorage 用量、重畫耗時 |

`hunt.js` 以前會固定回報一項「normalize 往返後欄位不同」(範例資料少了預設欄位),現在已經補齊、不會再出現。
如果又出現,先看是不是新增了欄位但 `sampleData()` 沒帶(2026-09 加 `netWorthHistory[].items` 時就是這樣),
不要直接當成誤報。

## 為什麼要有 longrun

有些問題只有長期使用才會浮現,例如每日備份把 localStorage 撐爆、
重畫隨資料量變慢。這個測試把五年、十五年的使用壓縮成幾秒鐘跑完。
