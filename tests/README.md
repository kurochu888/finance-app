# 測試

改完 `app.template.html` 之後:

```sh
python3 build.py     # 產生三個版本
tests/run.sh         # 跑全部測試
```

| 檔案 | 測什麼 |
|---|---|
| `smoke.js` | 功能與計算:五個分頁能不能畫、損益、XIRR、曝險、撤退門檻、還款分段利息、配息、備份還原、CSV、圖表互動。三個版本各跑一次 |
| `hunt.js` | 邊界情況:空白或重複的標的代號、刪掉還有紀錄的標的、賣超過持股、未來日期的還款、負數輸入 |
| `charts.js` | 圖表:兩點、一年 250 點、滿載 1000 點、全等值、負數、極大極小、有缺洞;檢查座標不跑出畫布、沒有 NaN、可點區域數量,以及點下去說明列與游標線會不會跟著動 |
| `audit.js` | 版面密度盤點:每個小分頁有幾張卡、幾個大字、幾段說明、多少字。不是通過/失敗,是給人看的數字,用來檢查有沒有又變雜亂 |
| `cloud.js` | 雲端同步(假後端):首次拉取、寫入回音、別台改動、打字中先擱著、寫入失敗、壞資料防護、匯入驗證 |
| `ids.js` | 重構後的完整性:同一畫面沒有重複 id、`<div>` 開合相符、輸出不含樣板殘骸(`${`、`undefined`、`NaN`),以及 refreshLeverage 要更新的每個 id 都真的存在 |
| `stress-live.js` | 壓力測試在打字時要即時更新(不能等到失焦才算) |
| `longrun.js` | 15 年長期使用:把時鐘換掉,模擬每天開 app、記帳、買賣、崩盤動用桶金、反彈減碼還款,追蹤資料量、localStorage 用量、重畫耗時 |

`hunt.js` 會固定回報一項「normalize 往返後欄位不同」——那是誤報,
只是補上預設欄位(`amount: undefined → 0`),沒有掉資料。

## 為什麼要有 longrun

有些問題只有長期使用才會浮現,例如每日備份把 localStorage 撐爆、
重畫隨資料量變慢。這個測試把五年、十五年的使用壓縮成幾秒鐘跑完。
